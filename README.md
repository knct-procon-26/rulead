# Rulead 開発参加方法

このファイルでは、Rulead開発に参加するための方法をまとめています。
なお、厳密には間違っている説明もありますが、厳密性にとらわれると初心者に嫌われてしまいますから、わかりやすい説明を採用しています。

## ここで用いる用語解説

Git - バージョンを管理するアプリ。「コミット(commit)」や「ブランチ(branch)」など難しそうな概念が出てくるが、名前が難しいだけ。仕組みをちゃんと考えれば難しくない。  
コミット(commit) - ファイルの変更履歴をローカルリポジトリに記録（セーブ）すること。もしくは、セーブされたもの。  
ブランチ(branch) - コミット履歴を分岐して記録していくためのもの。  
GitHub - ウェブサイト上でプログラムを管理できる便利なサービス。ここで、プログラムをチームメンバーと共有したり編集したりできる。Gitでバージョン管理しているものをそのままGitHub上で管理できる。  
ローカル - あなたが今使っているパソコンのこと。  
リモート - GitHubとか、あなたのパソコンから離れた場所にあるサービスやサーバー。  
VSCode - プログラムを書くためのアプリ。  
ターミナル - コマンド（文字で直接パソコンに命令を出せる）を実行できる場所。検索から「cmd」と打ってもらっても出てくるが、基本的にVSCodeを開いて「ctrl + t」で出てくるものを使えばよい。  
DB - たくさんの情報を管理するシステム

## 開発の流れ

### 1.できそうなissueを見つける

![find issue](/document/find_issue.png)

まず、issueの中からできそうなものを選んでください。
ラベルを参考にするとよいかもしれません。
「小 規模」「中 規模」「大 規模」といった規模観や、
「簡単」「普通」「難しい」といった難易度、
「新機能」「バグ」「デザイン」などのジャンルが設定されています。

> [!IMPORTANT]
> 開発を始める前に、その issue に「これに取り組んています」といったコメントをつけて参加して下さい

### 2. ローカルにコードを持ってくる

#### git clone

ここは、開発環境構築でやった人（つまり、ローカルにすでにruleadのフォルダがある人）はスキップして良いです。

![git clone](/document/git_clone.png)

ターミナルに、`git clone https://github.com/knct-procon-26/rulead.git` と入力して実行してください。
すると、GitHubにある共有されているプログラムをローカルに持ってくることができます。

#### git pull

ここは、VSCodeを開いて開発を始めるたびに **必ず** 実行してください。

![git pull](/document/git_pull.png)

ターミナルに `git pull` と入力して実行してください。
そもそも、ローカルにあるプログラムは古いものです。
`git pull` をすることで、GitHubにある最新のソースコードをローカルに持ってくることができます。

### 3.ブランチを切る

「ブランチを切る」と習慣的に言いますが、実際には、ローカルにあなたが開発するための専用の場所を作るようなものです。
今、あなたは `main` ブランチという場所にいるでしょう。（ `git branch` で確認できます）
（もし、`git branch` を実行して main ブランチ以外にいた場合は、 `git checkout main` で main ブランチに移動しましょう）
そこは、とても貴重な場所です。「全ての道はローマに通ず」といいますが、開発においては「全てのブランチはmainに通ず」るのです。
main はプログラムの終着点みたいなもので、そこであなたがプログラムを書き始めると、全員の迷惑になるかもしれません。
そこで、ブランチを切って、あなたが自由にコミットできる場所（ブランチ）を作りましょう！

![checkout branch](/document/checkout_branch.png)

次のコマンドを実行してください。

```
git checkout -b {ここに、ブランチの名前を入力}
```

ブランチの名前は、何をやっているかわかりやすいように、英語かつ主語を省略したものがいいでしょう。ただ、英文のスペースは `_` にしなければいけません。
翻訳やらAIやらでブランチ名を作ってもらってもいいですが、難しければ英単語でも良いです。

### 4.コーディングをしてコミットする

好きなようにコードを書いてください。普段通りに開発できます。
ある程度完成したら、コミットしましょう。
以下、VSCodeでの操作方法を説明します。

左のアイコンが縦に並んでいるものから、画像の物を押してください。
![git tab](/document/git_tab.png)

そして、「変更」と書かれているものにマウスを持ってくると、＋が表示されるのでそれを押してください。
![staging button](/document/staging_button.png)

最後に、左上のテキストボックスに何をしたかを簡潔に書いて、コミットボタンを押すことでGitにコミットできます。
![commit](/document/commit.png)

※コミットする場所がちゃんとあなたの作ったブランチかどうか確認すること。 `git branch` で確認できます。

### 5.ローカルのコミットをリモートに持っていく

コミットはできましたが、あくまでローカルのGitに変更内容を保存しただけです。
そこで、GitHubにコードを保存します（プッシュという）。

![git push](/document/git_push.png)

またもターミナルで次のコマンドを実行します

```
git push origin {ここに、ブランチの名前を入力}
```

ブランチの名前は、最初にあなたが決めたブランチの名前と同じにしてください。
こうして、ローカルの情報をリモートに持っていくことができます。

### 6.プルリクエストを作成する

ようやく、リモートにあなたの書いたコードがアップされましたが、まだ、終着点のmainブランチにコードが反映されていません。
そこで、「反映してください」という懇願書としてプルリクエスト(Pull Request)を作りましょう！
プルリクエストを作ったら、あとはチームリーダーがコードの確認・修正したのち、マージ（mainブランチに反映する）します。

いつも通り、[Rulead の GitHub サイトに戻りましょう](https://github.com/knct-procon-26/rulead) 。
すると、以下のように、`{あなたのブランチ名} had recent pushes ?? seconds ago` とか書かれているので、右の `Compare & pull request` ボタンを押します。
※ もしもこのような表示が現れない場合は、`Pull requests` タブの `New pull request` ボタンから手動で行うこともできます。その場合はbaseをmainに、compareをあなたのブランチ名にするとよいでしょう。
![Pull Request](/document/pull_request.png)

すると、入力できる画面が映るので、プルリクエストのタイトルと説明文を分かりやすく入力してください（リーダーが確認するのでわかりやすいと嬉しいです）
ただし、重要な点として、説明欄(description)に `close #1` のように、`close` に続けてあなたの取り組んだissueの番号を入力するようにしてください。
すると、プルリクエストとissueが連結されて整理されます。
実際の例は以下の通りです。

![PR sentence](/document/PR_sentence.png)

これを十分に書き終えたら、右下の `Create pull request` ボタンを押してください。
これで、あなたは一つのissueを解決できました！

### 7.最後に

プルリクエストが送ることができ、無事にマージされたらほかのissueに取り組みたくなるでしょう。
だから、1,2を終わらせた後に 3.ブランチを切る ことを始めようとするかもしれません。
その前に、今のブランチが、さっきまで作業をしていたブランチのままになっているかもしれません。
そこで、`git checkout main` で、mainブランチに一度移動しておきましょう。
現在地は `git branch` で表示されます。

## 開発中に使いがちなコマンド

#### `npm install`

javascript/typescriptで使っている必要なファイルやらを全部インストールします！
これを最初に実行しないと何もできないので注意！

#### `docker compose up --build`

バックエンドを動かします。このコマンドで、docker-compose.ymlに従って、qdrant/postgresql/api serverを全部動かせます。
注意点として、Windowsであれば、Docker Desktopを起動していないと実行できません。
また、環境変数とエンドポイントの設定もしないと動きません。詳しくは、[バックエンド動かすために](#バックエンドを動かすために) を参照ください。

#### `npm run start -w @rulead/client`

クライアントを動かして、アプリをandroid emulator上で動かします。
ただし、これは内部的にはexpo startであり、react-native-mapsなどのマップ表示系などには相性が悪く、マップを動かそうにも動かせません。
そこで、時間はかかりますが、以下のコマンドでマップも表示できるようになります

#### `npm run android -w @rulead/client`

androidをexpo goというものを経由せずに本当にビルドします。実際にアプリにビルドするもんですから初回は重いし時間がかかります。
ただ、本番環境に最も近いです。マップ系を取り扱わなければならないときはこちらのコマンドをどうぞ。

### `docker compose down`

バックエンドをちゃんと終了します。すべてのコマンドは、ctrl+cで止められますが、ちゃんと終了したい場合はこのコマンドをうつように。

## バックエンドを動かすために

`docker compose up --build` で動くとは言いましたが、事前の設定も必要です。

### 環境変数

ルートディレクトリ および apps/client を見ると、`.env.example` というファイルがあります。
これは、`.env` ファイルの記述例を記入したものです。
`.env` ファイルは、環境変数（パソコンの基本ソフト（OS）が管理している、すべてのプログラムから共通で参照できる「名前と値のペアの設定情報」のこと）を設定するファイルのことです。
`KEY=VALUE`という形をしています。

しかし、肝心の `.env` ファイルがないことに気が付くでしょう。意図的です。`.gitignore` ファイルでgitにコミットできないように制限をかけています。なぜなら、環境変数に書く内容には一般に知られたくない機密情報が含まれているからです。
例えば、他社製品を使うときにはAPIキーが必要となりますが、このキーが外部に漏れるとAPI使われ放題となり、とんでもない請求が飛んできます。
それを防ぐために、`.env` ファイルはgitにコミットできない（つまりはGitHubにアップロードできない）ようにしています。

しかし、もちろん開発の場では、`.env` ファイルがないとOpenAIやらGoogle Mapやらが使えません。
だから、最初に設定が必要となります。
基本的には、`.env.example` をその場所にコピペして、そのコピーしたファイルの名前を `.env` ファイルに変更してください。
その後、`なんちゃらかんちゃら=`　の続きに適するものを入れるのですが、やはりその内容もこのファイルには書けないので、個別に教えます。

具体的には、以下の通りです。

#### ルートディレクトリのenv

PORT - apiサーバーを公開するポート番号。とりあえず3000でよい。  
OPENAI_API_KEY - ChatGPTをアプリで使うために必要。機密情報なので、聞いたら教えます。  
JEV_API_KEY - Jevをアプリで使うために必要。機密情報なので、聞いたら教えます。  
GOOGLE_TRANSLATION_API_KEY - Google翻訳をアプリで使うために必要。機密情報なので、聞いたら教えます。  
POSTGRES_USER - DB のユーザーネーム。好きなようにどうぞ。  
POSTGRES_PASSWORD - DB のパスワード。好きなようにどうぞ。  
POSTGRES_DB - DB の名前。好きなようにどうぞ。  
DATABASE_URL - postgresql://{ここにPOSTGRES_USERの値}:{ここにPOSTGRES_PASSWORDの値}@localhost:5432/{ここにPOSTGRES_DBの値}  
QDRANT_URL - QdrantのURL。基本、http://localhost:6333 で問題ありません。

#### apps/clientのenv

GOOGLE_MAPS_API_KEY - Google maps api を使うためのもの。機密情報なので、聞いたら教えます。

### エンドポイント

`apps/client/constants/Debug.ts` の中身の `"http://localhost:3000/"` の部分は人によって変えなければなりません。
ただ、私は実機で試しているけどエミュレータなら、`"http://localhost:3000/"` のままでもいいかも。

設定する値としては、`ipconfig` コマンドを実行してもらって、その中の IPv4アドレス をコピペしてください。
デプロイ時には正しい値に変更しますが、それまでは、手動で変える感じです。

### overpassの代替

もともとoverpassを使っていましたが、エラーが多発するので公園のジオメトリ情報を抽出して利用する形にしました。
事前にwslでscripts/build-osm-areas.sh をローカルで実行（2.5GB）して、サーバー起動後に

```
docker compose cp osm-work/osm-areas.geojsonseq.gz backend:/tmp/
docker compose exec backend bun run scripts/importOsmAreas.ts /tmp/osm-areas.geojsonseq.gz
```

を実行してください。

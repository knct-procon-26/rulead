# Rulead 開発参加方法

このファイルでは、Rulead開発に参加するための方法をまとめています。
なお、厳密には間違っている説明もありますが、厳密性にとらわれると初心者に嫌われてしまいますから、わかりやすい説明を採用しています。

## ここで用いる用語解説

Git - バージョンを管理するアプリ。「コミット(commit)」や「ブランチ(branch)」など難しそうな概念が出てくるが、名前が難しいだけ。仕組みをちゃんと考えれば難しくない。
コミット(commit) - ファイルの変更履歴をローカルリポジトリに記録（セーブ）すること。もしくは、セーブされたもの。
ブランチ(branch) - コミット履歴を分岐して記録していくためのもの。
GitHub - ウェブサイト上でプログラムを管理できる便利なサービス。ここで、プログラムをチームメンバーと共有したり編集したりできる。Gitでバージョン管理しているものをそのままGitHub上で管理できる。
ローカル - あなたが今使っているパソコンのこと。
リモート - GitHubとか、あなたのパソコンから離れた場所にあるサービスやサーバー。
VSCode - プログラムを書くためのアプリ。
ターミナル - コマンド（文字で直接パソコンに命令を出せる）を実行できる場所。検索から「cmd」と打ってもらっても出てくるが、基本的にVSCodeを開いて「ctrl + t」で出てくるものを使えばよい。

## 開発の流れ

### 1.できそうなissueを見つける

![find issue](/document/find_issue.png)

まず、issueの中からできそうなものを選んでください。
ラベルを参考にするとよいかもしれません。
「小 規模」「中 規模」「大 規模」といった規模観や、
「簡単」「普通」「難しい」といった難易度、
「新機能」「バグ」「デザイン」などのジャンルが設定されています。

### 2. ローカルにコードを持ってくる

#### git clone

ここは、開発環境構築でやった人（つまり、ローカルにすでにruleadのフォルダがある人）はスキップして良いです。

![git clone](/document/git_clone.png)

ターミナルに、`git clone https://github.com/knct-procon-26/rulead.git` と入力して実行してください。
すると、GitHubにある共有されているプログラムをローカルに持ってくることができます。

#### git pull

ここは、VSCodeを開いて開発を始めるたびに **必ず** 実行してください。

![git pull](/document/git_pull.png)

ターミナルに `git pull` と入力して実行してください。
そもそも、ローカルにあるプログラムは古いものです。
`git pull` をすることで、GitHubにある最新のソースコードをローカルに持ってくることができます。

### 3.ブランチを切る

「ブランチを切る」と習慣的に言いますが、実際には、ローカルにあなたが開発するための専用の場所を作るようなものです。
今、あなたは `main` ブランチという場所にいるでしょう。（ `git branch` で確認できます）
（もし、`git branch` を実行して main ブランチ以外にいた場合は、 `git checkout main` で main ブランチに移動しましょう）
そこは、とても貴重な場所です。「全ての道はローマに通ず」といいますが、開発においては「全てのブランチはmainに通ず」るのです。
main はプログラムの終着点みたいなもので、そこであなたがプログラムを書き始めると、全員の迷惑になるかもしれません。
そこで、ブランチを切って、あなたが自由にコミットできる場所（ブランチ）を作りましょう！

![checkout branch](/document/checkout_branch.png)

次のコマンドを実行してください。

```
git checkout -b {ここに、ブランチの名前を入力}
```

ブランチの名前は、何をやっているかわかりやすいように、英語かつ主語を省略したものがいいでしょう。ただ、英文のスペースは `_` にしなければいけません。
翻訳やらAIやらでブランチ名を作ってもらってもいいですが、難しければ英単語でも良いです。

### 4.コーディングをしてコミットする

好きなようにコードを書いてください。普段通りに開発できます。
ある程度完成したら、コミットしましょう。
以下、VSCodeでの操作方法を説明します。

左のアイコンが縦に並んでいるものから、画像の物を押してください。
![git tab](/document/git_tab.png)

そして、「変更」と書かれているものにマウスを持ってくると、＋が表示されるのでそれを押してください。
![staging button](/document/staging_button.png)

最後に、左上のテキストボックスに何をしたかを簡潔に書いて、コミットボタンを押すことでGitにコミットできます。
![commit](/document/commit.png)

※コミットする場所がちゃんとあなたの作ったブランチかどうか確認すること。 `git branch` で確認できます。

### 5.ローカルのコミットをリモートに持っていく

コミットはできましたが、あくまでローカルのGitに変更内容を保存しただけです。
そこで、GitHubにコードを保存します（プッシュという）。

![git push](/document/git_push.png)

またもターミナルで次のコマンドを実行します

```
git push origin {ここに、ブランチの名前を入力}
```

ブランチの名前は、最初にあなたが決めたブランチの名前と同じにしてください。
こうして、ローカルの情報をリモートに持っていくことができます。
